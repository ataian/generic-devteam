## Evidence output

Follow the [tool output contract](../SKILL.md#tool-output). Compare full inventories, bytes, mappings and native-loaded content using documented native text normalization. Keep full comparisons privately. Omit full successful payloads from output.

- Skills: actual consumer context, resolved source, discovery/loading result and required reference coverage.

- Unverified items: report separately from successful checks.

Keep directories 0700 and files 0600. Keep proposals, backups and journals when the update requires them.
3. Use **Team configured; setup outputs verified** only after required outputs and baseline pass. Otherwise give the exact incomplete binding, preserved progress, next action and required authorization. For shared prerequisites, use only disclosed first-installation or separately approved [change scope](integrations.md).
4. On resume, reconcile saved data with relevant native objects, correct stale prose and continue the incomplete step. Do not repeat confirmed choices or successful creates.

Setup verifies configuration, availability and delivery. Exclude live behavior, project readiness, source/SDK research, behavioral experiments and general timeout/retry/rate-limit investigations from setup gates.

For a requested file update follow the [update contract](update.md): semantic review, activity/dependency decisions, local-edit preservation, legacy unknown baselines, journals and guarded rollback. Report `applied`, `skipped`, `failed` and retained files per team. Runtime reload needs separate evidence.

For every requested team update, read back the [mandatory upstream companion status](update.md#required-upstream-companion-update), including at the same Maker version. Deferred required assets or effective loading keep the team update incomplete. Report them separately from successful file application.
